# Tally algorithm

`tally()` is a pure function. Given the same (poll, ballots, chain snapshot),
every correct implementation returns the same result — byte-for-byte. This is
the property that makes OC Vote trust-minimized: anyone can re-run the tally and
check.

## Signature

```ts
function tally(opts: {
    poll: Poll;
    ballots: Ballot[];
    // UTXOs `address` held at `blockHeight`: each { value, confirmed_height }.
    utxosAt: (address: string, blockHeight: number) => Utxo[] | Promise<Utxo[]>;
    // Required when poll.snapshot_block is "deadline"; see resolvePollSnapshot().
    snapshotBlock?: number;
    // Current tip: throws E_REORG if the snapshot has fewer than 6 confirmations.
    tipHeight?: number;
    // Secret-mode polls: returns a ballot's option once the reveal key is published.
    unseal?: (ballot: Ballot) => Promise<string | null> | string | null;
    // Preferred: named arguments can't be swapped.
    verify?: (a: {
        address: string;
        message: string;
        signature: string;
    }) => Promise<boolean> | boolean;
    // Positional, and vote-core's order is (address, message, signature), unlike
    // every sibling package. A sibling's verifier compiles here and checks nothing.
    verifyBip322?: (
        address: string,
        message: string,
        signatureB64: string
    ) => Promise<boolean> | boolean;
    skipSignatures?: boolean; // for offline / cached-signature re-tallies
}): Promise<TallyResult>;
```

`tally` throws unless it gets `verify`, `verifyBip322` or an explicit
`skipSignatures`, so it never counts unverified ballots by accident. It also
throws on a `"deadline"` poll without `snapshotBlock`: resolve the block with
`resolvePollSnapshot(poll, mempoolBlockTimeSource())` (or your own node) and
pass `snapshotBlock: snap.height`.

The function is async only because `utxosAt` and the verifier may be. Everything
else is deterministic synchronous computation.

## Steps

### 1. Verify the poll, then each ballot

- Verify `poll.sig.value` as a BIP-322 signature by `poll.creator` over the poll
  id: the SHA-256 of the canonical poll with `sig.value` set to `""`. If it
  fails, the whole tally fails with `E_BAD_SIG`.
- Drop a ballot whose `poll_id` is not this poll's, whose `voter` is not a
  mainnet address, whose `created_at` is after `poll.deadline`, or whose
  signature over its ballot id does not verify.
- Public polls: drop a ballot whose `option` is null or is neither `"withdraw"`
  nor one of the poll's option ids. Secret polls: drop a ballot with no
  `secret`.

Invalid ballots are **silently dropped** (not failing the whole tally). This is
important: nobody can block a tally by publishing a bad ballot.

### 2. One ballot per voter

If a voter has several valid ballots, the poll's `tiebreak` picks one: `latest`
takes the greatest `created_at`, `first` the least. Equal times are broken by
ballot id, greater for `latest` and lesser for `first`. Relays keep every ballot
a voter publishes (each is its own Nostr event), so this step, not the relay, is
what decides. Conformance vectors `v04` and `v06` test it.

### 3. Reveal (secret polls)

Without the reveal key the result is `{ "state": "awaiting_reveal" }`. With it,
each voter's chosen ballot is unsealed and its commitment checked; a voter whose
ballot does not open to a valid option is dropped.

### 4. Snapshot block

`poll.snapshot_block` if it is a height. If it is `"deadline"`, the block whose
median time past is the greatest at or before the deadline, with at least six
confirmations.

### 5. Weigh and sum

For each remaining voter, call `utxosAt(voter, snapshot)` and apply the
[weight mode](/vote/weight-modes). A voter who chose `"withdraw"` or whose
weight is zero adds nothing and is not counted in `turnout`.

```
for voter, ballot in chosen:
    if ballot.option == "withdraw": continue
    w = weight(poll.weight_mode, utxos_at(voter, snapshot))
    if w == 0: continue
    tallies[ballot.option] += w
    turnout.voters += 1
    turnout.weight += w
```

`utxosAt` is the ONLY network-dependent step besides the snapshot height. A
caller with an offline chain snapshot (e.g., a compact block-filter database)
can supply their own `utxosAt` and compute the tally fully offline.

## Output shape

```json
{
    "state": "tallied",
    "snapshot_block": 900000,
    "turnout": { "voters": 2, "weight": 210000000 },
    "tallies": { "keep": 180000000, "midnight": 30000000 }
}
```

Every option appears in `tallies`, with `0` if nobody chose it. There is no
winner field: which tally wins, and whether turnout is enough, is the caller's
policy. Two independent implementations that disagree on any field have a bug.

## Conformance

The 6 canonical vectors in `oc-vote-protocol/test-vectors/`:

| Vector | What it pins                                                                   |
| ------ | ------------------------------------------------------------------------------ |
| `v01`  | Minimal public poll — one voter, `sats`                                        |
| `v02`  | `sats` with three voters, one under `min_sats` and weighing zero               |
| `v03`  | `sats_days` with a 180-day cap; one voter with two UTXOs, one past the cap     |
| `v04`  | Vote change — one voter, two ballots, `tiebreak: latest` picks the later       |
| `v05`  | Secret ballot — option null before the reveal, the commitment binds the choice |
| `v06`  | `tiebreak: first` — three ballots from one voter, a tie broken by `ballot_id`  |

`@orangecheck/vote-core` passes all 6 on every CI run. A reimplementation in
another language is conformant iff it also passes all 6.

## Edge cases

- **Voter has no UTXOs at snapshot.** Weight = 0. The ballot is valid but
  contributes nothing and is not in `turnout`.
- **Ballot after the deadline.** Dropped in step 1, so a late ballot can't race
  the tally.
- **Two ballots from the same voter with the same `created_at`.** The ballot id
  breaks the tie, per `tiebreak`.
- **Zero valid ballots.** Every option tallies `0`, and `turnout` is
  `{ "voters": 0, "weight": 0 }`.
