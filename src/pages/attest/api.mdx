# OC Attest HTTP API

The hosted API at `https://attest.ochk.io/api/*` is a **reference deployment**
of OC Attest. `https://ochk.io/api/check`, `/api/verify` and `/api/discover`
forward there and answer the same. `/api/challenge` is served by `ochk.io`, the
auth host. The same checks run in your own code through
[`@orangecheck/sdk`](/sdk/sdk/README). Every route is documented here.

Rate limits are per IP, per minute: `/api/check` and `/api/discover` 60,
`/api/stats` 30, `/api/challenge` 30, `/api/verify` 10,
`/api/publish-attestation` 5. Response shape is stable; new optional fields may
be added, existing fields will not change meaning.

## `GET /api/check`

The load-bearing sybil-gate primitive. One call, one answer.

### Request

```
GET /api/check?addr=bc1q...&min_sats=100000&min_days=30
GET /api/check?id=<attestation_id>&min_sats=100000
GET /api/check?identity=github:alice&min_sats=50000
```

| Param      | Required         | Notes                                      |
| ---------- | ---------------- | ------------------------------------------ |
| `addr`     | at least one of… | Bitcoin address                            |
| `id`       | …these three     | Attestation ID (64-char hex)               |
| `identity` |                  | `protocol:identifier`, e.g. `github:alice` |
| `min_sats` | optional         | Integer; default 0                         |
| `min_days` | optional         | Integer; default 0                         |

### Response — 200

```json
{
    "ok": true,
    "sats": 125000,
    "days": 47,
    "score": 30.12,
    "attestation_id": "a3f5b8c2...",
    "address": "bc1q...",
    "identities": [{ "protocol": "github", "identifier": "alice" }],
    "network": "mainnet"
}
```

### Response — below threshold (200, `ok: false`)

```json
{
  "ok": false,
  "sats": 50000,
  "days": 12,
  "score": 15.15,
  "attestation_id": "a3f5b8c2...",
  "address": "bc1q...",
  "identities": [...],
  "network": "mainnet",
  "reasons": ["below_min_sats", "below_min_days"]
}
```

### Response — not found (404)

```json
{ "ok": false, "reasons": ["not_found"] }
```

Cached 60 s by default.

## `POST /api/verify`

Raw attestation verification — no relay lookup, no thresholds. Give it
`(addr, msg, sig)`, get back full codes + metrics.

### Request

```json
{
    "addr": "bc1q...",
    "msg": "orangecheck\nidentities: ...\n...",
    "sig": "AUBH..."
}
```

`scheme` may still be sent, as `bip322` or `legacy`, and is ignored: the
signature's bytes decide which it is.

### Response — 200

```json
{
    "ok": true,
    "codes": ["sig_ok_bip322", "bond_confirmed"],
    "network": "mainnet",
    "attestation_id": "a3f5b8c2...",
    "identities": [{ "protocol": "github", "identifier": "alice" }],
    "metrics": { "sats_bonded": 125000, "days_unspent": 47, "score": 30.12 }
}
```

`metrics` is present only when `ok` is true. No cache.

## `/api/challenge`

Signed-challenge auth — prove control of an address in real-time.

### `GET /api/challenge?addr=bc1q…&audience=https://example.com&purpose=login`

Issue a short-lived message for the user to sign.

Response:

```json
{
    "message": "orangecheck-auth\n...",
    "nonce": "a3f5b8c2...",
    "expiresAt": 1777014000000,
    "expiresAtIso": "2026-04-24T07:00:00Z"
}
```

`expiresAt` is epoch milliseconds. An optional `ttl` sets the lifetime in
seconds, 30 to 3600.

### `POST /api/challenge`

Verify a signed response.

```json
{
    "message": "orangecheck-auth\n...",
    "signature": "AUBH...",
    "expectedNonce": "a3f5b8c2...",
    "expectedAudience": "https://example.com",
    "expectedPurpose": "login"
}
```

Response: `{ ok: true, address: "bc1q..." }` on success,
`{ ok: false, reason: "invalid_challenge" }` otherwise.

The public primitive is deliberately generic — no session cookies, no account
side effects. The caller is responsible for nonce replay prevention. If you want
the session-aware variant, see
[Sign in with Bitcoin](/attest/guides/sign-in-with-bitcoin).

## `GET /api/discover`

List attestations for a subject — a summary of each one the relays hold, most
recent first.

```
GET /api/discover?addr=bc1q...
GET /api/discover?id=<attestation_id>
GET /api/discover?identity=github:alice
```

`limit` caps the list, 1 to 100, default 50. `total` counts every match before
the cap.

Response:

```json
{
    "count": 1,
    "total": 1,
    "attestations": [
        {
            "attestation_id": "a3f5b8c2...",
            "address": "bc1q...",
            "scheme": "bip322",
            "identities": [{ "protocol": "github", "identifier": "alice" }],
            "issued_at": "2026-04-20T12:00:00Z",
            "expires_at": "2027-04-20T12:00:00Z",
            "verification_url": "https://attest.ochk.io/attest/a3f5b8c2...",
            "relay_hints": []
        }
    ]
}
```

Each summary leaves out the message and the signature, and nothing is verified:
use `/api/check` or `/api/verify` for that. Use this when you need to see
historical attestations for an address, not just "does the latest meet
thresholds." Cached 60 s.

## `POST /api/publish-attestation`

Broadcast an envelope you built and signed with `createAttestation()`. The
server recomputes the id, re-verifies the signature, builds the Nostr event from
the signed message alone, signs that outer event with attest.ochk.io's service
key, and sends it to its relays.

```json
{
    "envelope": {
        /* AttestationEnvelope */
    }
}
```

Response — 200:

```json
{
    "ok": true,
    "success_count": 3,
    "total_count": 4,
    "success": ["wss://..."],
    "failed": [{ "relay": "wss://...", "reason": "..." }],
    "event_id": "...",
    "pubkey": "..."
}
```

A 200 can carry `success_count: 0`, so read `success` and `failed`. The service
key vouches for delivery only; the BIP-322 signature inside is still the proof.
An envelope that binds a `nostr:` identity is refused with 422
`nostr_binding_requires_nip07`: that npub must sign the event itself. Other
refusals are 400 (`invalid_json`, `missing_envelope`, `missing_field`) and 422
(for example `attestation_id_mismatch`, `signature_invalid`,
`message_too_large`). The full list is in `/api/openapi`.

## `GET /api/stats`

Aggregate counts over the newest attestations on attest.ochk.io's relays, up to
500 per relay, deduplicated by attestation id: totals by scheme, identity
bindings by protocol, unique addresses, and the `bond:` amounts declared in
signed messages (declared, not checked against the chain). Cached 10 minutes;
`cached_at` says when it was computed and `window_minutes` is that cache life.

## Status codes

| Code                     | Severity | Meaning                                                                              |
| ------------------------ | -------- | ------------------------------------------------------------------------------------ |
| `sig_ok_bip322`          | success  | BIP-322 signature verified                                                           |
| `sig_ok_legacy`          | success  | Legacy signmessage verified, any address                                             |
| `sig_invalid`            | error    | Signature does not match                                                             |
| `sig_unsupported_script` | error    | BIP-322 full or proof-of-funds signature                                             |
| `invalid_scheme`         | error    | Not sent: the signature decides the scheme                                           |
| `decode_error`           | error    | Canonical message malformed                                                          |
| `invalid_attestation_id` | error    | Claimed ID doesn't match sha256(msg)                                                 |
| `bond_confirmed`         | success  | Chain lookup returned usable metrics                                                 |
| `bond_zero`              | error    | Address holds no confirmed UTXOs                                                     |
| `bond_pending`           | info     | Only unconfirmed UTXOs found                                                         |
| `bond_insufficient`      | error    | `bond:` extension exceeds confirmed balance                                          |
| `bond_malformed`         | error    | `bond:` value is not a valid integer                                                 |
| `below_min_sats`         | error    | Policy threshold — `/api/check` only                                                 |
| `below_min_days`         | error    | Policy threshold — `/api/check` only                                                 |
| `stake_shared`           | error    | Address also backs another handle on the same protocol — `/api/check?identity=` only |
| `aud_mismatch`           | warn     | Signed audience ≠ expected (challenge flow)                                          |
| `expired`                | error    | Signed `expires` passed or unreadable                                                |
| `not_yet_valid`          | error    | Signed `issued_at` ahead of the clock                                                |
| `network_testmode`       | warn     | Signature is on testnet/signet                                                       |
| `bad_request`            | error    | Structural problem with request body                                                 |

## HTTP status vs. status code

The HTTP status tells you the request was processable; the `codes` / `reasons`
fields tell you what the verification found. Don't conflate them.

| HTTP | Meaning                                                  |
| ---- | -------------------------------------------------------- |
| 200  | Request was valid and the verifier ran                   |
| 400  | Request shape was wrong (missing `addr`, malformed JSON) |
| 401  | `/api/auth/*` session rejected                           |
| 403  | Cross-site POST to a browser-only endpoint               |
| 404  | `/api/check` subject not found                           |
| 429  | Rate limit exceeded                                      |
| 500  | Verifier crashed — file a bug                            |
