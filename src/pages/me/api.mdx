# ochk.app · HTTP API

**The hosted me.ochk.io substrate exposes the contracts the SDK calls into.**
The SDK is the canonical integration path; this page is the raw HTTP surface for
clients that aren't TypeScript or that want to bypass the SDK.

Every endpoint is at `https://me.ochk.io/api/...` unless noted. Auth is by
cross-subdomain `oc_session` cookie (`Domain=.ochk.io`, HttpOnly, SameSite=None,
Secure) issued by the auth host at `https://ochk.io`, OR by an
`Authorization: Bearer <jwt>` header (cross-domain integrators that captured the
session token from the popup-signin postMessage). Mutating endpoints are
rate-limited per IP per bucket; limits are returned in `X-RateLimit-*` headers.

## Sign-in endpoints (auth host · `https://ochk.io`)

The session cookie is issued by the family auth host, not by me.ochk.io
directly. The sign-in popup at `me.ochk.io/popup/signin` calls these endpoints
cross-origin with credentials — they are CORS-allowed for any `*.ochk.io`
browser origin. ochk.app, on its own domain, calls them without credentials and
keeps the token they return in its own cookie.

| Method | Path                         | Purpose                                                                |
| ------ | ---------------------------- | ---------------------------------------------------------------------- |
| `POST` | `/api/auth/email-otp/start`  | issue a stateless OTP token + email a 6-digit code (rate-limited 5/hr) |
| `POST` | `/api/auth/email-otp/verify` | verify `{email, code, token}`, upsert account, set `oc_session` cookie |
| `GET`  | `/api/challenge`             | issue a fresh BIP-322 challenge to sign                                |
| `POST` | `/api/auth/signin`           | verify a signed BIP-322 challenge, upsert account, set `oc_session`    |
| `POST` | `/api/auth/logout`           | clear the `oc_session` cookie                                          |
| `GET`  | `/api/auth/me`               | crypto-only identity lookup; 401 otherwise                             |

> The sign-in popup at `me.ochk.io/popup/signin` is the client for these
> endpoints; `signInWithOc()` from `@orangecheck/me-client/popup` opens it.

## Authenticated · integrator event ingestion

`project_key` (in the body) identifies the billing project. The earner is either
`user_address` — the user's `did_oc`, inside the body you sign, which is how a
backend fires — or, from a browser, the signed-in user's cookie or
`Authorization: Bearer` token (see the note above). Sign the request with the
project signing secret (`X-OC-Signature`) — in **both** test and live mode. A
user session proves a user, never the paying project, so an unsigned POST is
admitted only when the session belongs to the project's own owner (the CLI
test-fire path). Anything else gets `401 project_auth_required`.

The header is `t=<unix-seconds>,v1=<hex>`, where `v1` is
`hmac_sha256(signing_secret, "${t}.${body}")` over the exact bytes you send. `t`
must be within the last 300 seconds and at most 60 seconds ahead of me.ochk.io's
clock. The same signed bytes are processed once: POSTing them again, with or
without an `Idempotency-Key`, returns the first event
(`idempotent_replay: true`, or `duplicate` per event in a batch) and bills
nothing. To retry, resend the same bytes, or sign again with the same
`Idempotency-Key`. Two identical bodies signed in the same second are one
request.

| Method | Path                          | Purpose                                                                            |
| ------ | ----------------------------- | ---------------------------------------------------------------------------------- |
| `POST` | `/api/integrator/event`       | fire a billable event under a project_key (live mode requires domain verification) |
| `POST` | `/api/integrator/event/batch` | fire 1–100 billable events in one call · per-event idempotency keys                |

Outside the project's [pay periods](/me/paying-users) both answer `200` with
`earned: false` (`not_paying` per event in a batch) and record nothing. Paying
users is optional.

A test project records events for the account that owns it and nobody else, so
you can try your integration on yourself. An event or batch naming anyone else,
by `user_address` or by session, answers `403 earner_not_project_owner` and
records nothing. A test project records at most 1,000 events a UTC day across
`/event`, `/event/batch` and the test-fire button, then
`429 test_project_daily_cap`, and at most 5,000 in all, then
`429 test_project_event_cap`. Every test project together records at most 2,000
events a UTC day, then `429 test_events_ceiling` until midnight UTC; live
projects never count toward it. A refused event records nothing and counts
toward none of these. To record events for your users, verify your domain and go
live.

`/event/batch` takes the person's own session, not `user_address`: the cookie,
or the token from the sign-in popup as `Authorization: Bearer`. Every event in a
batch earns for that person. A backend that names who earns fires
`/api/integrator/event` once per event.

### Signing an event

The request body is JSON. The fields, in any order:

| Field                 | Required | Meaning                                                                              |
| --------------------- | -------- | ------------------------------------------------------------------------------------ |
| `project_key`         | yes      | Your project, `pk_test_…` or `pk_live_…`                                             |
| `subtype`             | yes      | An event your project defined and enabled, built-in or your own                      |
| `user_address`        | backend  | Who earns: the person's `did_oc` from their sign-in token. Accepted only when signed |
| `payment_amount_sats` | some     | The payment, for an event priced as a share of one                                   |
| `action_label`        | no       | A short label shown on the receipt: up to 280 characters of plain text               |
| `note`                | no       | A note shown to the person: up to 280 characters of plain text                       |
| `is_agent`            | no       | `true` when an AI agent acted for the person                                         |

Sign the exact bytes you send, in one header:

```
X-OC-Signature: t=<unix seconds>,v1=<hex HMAC-SHA256(key, "<t>.<body>")>
```

The key is the signing secret **as text**, its characters as UTF-8 bytes: do not
hex-decode it. `<body>` is the raw request body, byte for byte. A `t` more than
300 seconds from the server's clock is refused. Send `Idempotency-Key` (up to
200 characters) to make a retry safe: a repeat answers the first result with
`idempotent_replay: true`.

In Python, with [`orangecheck`](/sdk/python) 2.3 or later:

```python
import json, os
import httpx
from orangecheck import sign_event

did_oc: str  # from verify_session(...).did_oc
user_id: str  # your own id for the same user

body = json.dumps({
    "project_key": os.environ["OC_PROJECT_KEY"],
    "subtype": "account_creation",
    "user_address": did_oc,
})
r = httpx.post(
    "https://me.ochk.io/api/integrator/event",
    content=body,  # the same string that was signed
    headers={
        "Content-Type": "application/json",
        "X-OC-Signature": sign_event(os.environ["OC_SIGNING_SECRET"], body),
        "Idempotency-Key": f"signup-{user_id}",
    },
)
```

Without the SDK, the header is
`f"t={t},v1=" + hmac.new(secret.encode(), f"{t}.".encode() + body_bytes, hashlib.sha256).hexdigest()`.

### What the event endpoint answers

| Status | `error` / `reason`                                       | Meaning                                                                                        |
| ------ | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 200    | `earned: true`                                           | Recorded. `event` is the receipt; `event.sub` is the person's pairwise id for your project     |
| 200    | `earned: false`, `reason: not_paying`                    | Outside your pay periods: nothing recorded or charged                                          |
| 400    | `invalid_user_address`                                   | `user_address` is not a `did:oc`                                                               |
| 401    | `invalid_signature`                                      | The header is there but does not verify (`stale_timestamp`, `bad_signature`, `invalid_format`) |
| 401    | `signature_required`                                     | A live project, or one requiring signed events, got an unsigned request                        |
| 401    | `project_auth_required`                                  | Unsigned, and not from the project owner's own session                                         |
| 401    | `earner_requires_signature`                              | `user_address` on an unsigned request                                                          |
| 402    | `escrow_depleted`                                        | Your balance cannot cover the event; sign-in is unaffected                                     |
| 403    | `domain_unverified`                                      | A live project whose domain is not verified                                                    |
| 403    | `earner_not_project_owner`                               | A test project's event names someone other than its owner                                      |
| 403    | `project_frozen`                                         | Frozen by the platform                                                                         |
| 409    | `idempotency_key_in_flight`                              | The same `Idempotency-Key` is still being processed; retry after `Retry-After`                 |
| 422    | the event key, `earning_below_one_sat`                   | Not a defined, enabled event; or it would pay the person nothing                               |
| 422    | `invalid_note`, `invalid_action_label`                   | Longer than 280 characters, not text, or with a character that hides or reorders text          |
| 429    | `identity_cap_reached`, `site_cap_exceeded`, rate limits | A per-person or per-site cap, or too many requests                                             |
| 429    | `test_project_daily_cap`                                 | A test project's 1,000 events for the UTC day are used                                         |
| 429    | `test_project_event_cap`                                 | A test project's 5,000 events in all are used                                                  |
| 429    | `test_events_ceiling`                                    | Every test project together used the 2,000 test events of the UTC day                          |

The per-person cap on class A events counts only events billed against live
escrow. A preview event spends nobody's allowance.

## Authenticated · integrator project lifecycle

| Method   | Path                                | Purpose                                                                                                                   |
| -------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/api/me/projects`                  | list every project owned by your identity                                                                                 |
| `POST`   | `/api/me/projects`                  | create a project, rate-limited 5/min, at most 25 per account. Pays nobody unless `pay: { action: 'add', … }` asks it to   |
| `GET`    | `/api/me/projects/[id]`             | per-project state · owner-gated                                                                                           |
| `POST`   | `/api/me/projects/[id]`             | update IntegratorPriceConfig (prices only; a name or domain in the body is ignored) · owner-gated, validates              |
| `PATCH`  | `/api/me/projects/[id]`             | rename: `{ display_name }`, 1–80 characters · owner-gated                                                                 |
| `POST`   | `/api/me/projects/[id]/domain`      | change the domain: `{ domain }`. Never verified: replaced at once. Verified: opens a move (see below)                     |
| `DELETE` | `/api/me/projects/[id]/domain`      | cancel an open move · owner-gated                                                                                         |
| `DELETE` | `/api/me/projects/[id]`             | delete project; refused while it holds sats or owes a step ([below](#deleting-a-project)) · owner-gated                   |
| `POST`   | `/api/me/projects/[id]/pay-periods` | when the project pays its users: `add`, `end`, `set_end`, `cancel` ([details](/me/paying-users)) · owner-gated            |
| `POST`   | `/api/me/projects/[id]/verify`      | run a domain-ownership check (DNS TXT, falls back to meta tag); during a move, checks the new domain · rate-limited 5/min |
| `DELETE` | `/api/me/projects/[id]/verify`      | reissue the verification token; a verified domain stays verified until its next check · owner-gated                       |
| `POST`   | `/api/me/projects/[id]/test-fire`   | fire a real envelope under this project_key (same pipeline as production) · owner-gated · for the smoke-test sandbox      |
| `GET`    | `/api/me/projects/[id]/events`      | live event stream for this project · owner-gated                                                                          |
| `GET`    | `/api/me/projects/[id]/webhooks`    | list registered webhooks · owner-gated                                                                                    |
| `POST`   | `/api/me/projects/[id]/webhooks`    | register a webhook URL · owner-gated                                                                                      |
| `POST`   | `/api/developer/webhook-test`       | test-fire a synthetic envelope at a registered webhook                                                                    |

A project's name, a custom event's label, a drop's label and a directory tagline
are text people read, so one rule applies to all of them: no character that
hides or reorders text, and never orangecheck's own name (`orangecheck`, `ochk`,
`ochk.io`, `ochk.app`, in any case, width or spacing). A name breaking it
answers `409 name_reserved` at create and rename; a label, a `422` naming it. An
account holds at most 25 projects (`409 project_limit_reached`).

### Moving a verified domain

A verified domain is what consent screens name and what every receipt records,
so it never changes in one step. `POST /api/me/projects/[id]/domain` on a
verified project opens a move: the project gets a `pending_domain` with its own
token, and keeps running on its current domain. Publish that token at the new
domain, exactly as for a first verification, then call `/verify`. When the check
passes, the new domain becomes the project's domain and the old one is kept in
`previous_domains`, so receipts recorded under it still belong to the project. A
failed check changes nothing.

Opening a move needs a fresh identity check, as revealing the signing secret
does: without one the call answers 401 `identity_reproof_required`. A frozen
project answers 409 `project_frozen`.

### Deleting a project

Deleting a project takes everything that only served it: its key, its webhooks
and their queued deliveries, an open handover offer, its release schedules, its
rate counters and its event index. What belongs to someone else stays: the
receipts people earned, the escrow ledger, payouts and release records.
Statements the project made about accounts stay too: a statement outlives the
project that made it, and still names it.

A delete checks first and deletes nothing while the project holds sats or owes a
step: it answers 409 with a `reason` and a `detail` sentence saying what to do
first. Once the checks pass, the project is gone at once: events, top-ups and
handovers sent to it answer as for a deleted project, and what only served it is
removed after.

| `reason`             | What to do first                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------- |
| `escrow_balance`     | The project holds sats in escrow (`balance_sats`). Refunds aren't self-serve yet: write to billing@ochk.io. |
| `escrow_held`        | An event is being charged right now. Wait a minute.                                                         |
| `escrow_settling`    | An event's charge is still being settled, within the hour.                                                  |
| `topup_open`         | A top-up invoice can still be paid. Wait until it expires, a little over an hour after it was made.         |
| `drop_open`          | A release schedule still holds what people earned. Turn it off, which releases what it holds at once.       |
| `connect_moving`     | Its Connect app is still being handed back after a handover. Try again in an hour.                          |
| `transfer_accepting` | Someone is accepting the project right now. Reload in a minute: it may already be theirs.                   |
| `connect_linked`     | A Connect app is linked to the project. Delete it first: Sign-in → Connect app → Delete.                    |

The same rules hold when orangecheck deletes a project.

## Response shapes

All authenticated 401s are `{ ok: false }` with
`Cache-Control: no-store, private` and `Vary: Cookie`. All 422 validation
failures return
`{ error: string, details?: [{ subtype?: string, message: string }] }`. All 429
rate-limit responses include a `Retry-After` header in seconds.

## Rate limits per bucket

| Bucket                      | Limit | Window |
| --------------------------- | ----- | ------ |
| `integrator.event`          | 120   | 60s    |
| `payment.authorize`         | 30    | 60s    |
| `wallet.send`               | 30    | 60s    |
| `webhooks.register`         | 10    | 60s    |
| `projects.test-fire`        | 20    | 60s    |
| `developer.projects.create` | 5     | 60s    |
| `verify-domain:<addr>`      | 5     | 60s    |

Limits are per IP, per bucket (except `verify-domain` which is per-account so
DNS retries don't get throttled by a noisy neighbor). Headers
`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Window` are emitted
on every rate-limited response. v1 buckets reset on cold start (per-instance
in-memory); production fronts every endpoint with an edge-level limiter.
