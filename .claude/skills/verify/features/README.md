# Docs feature map

`../features.json` is generated by `featuremap` and never edited by hand. The files
here hold the recipes. Each one declares the ids it covers in a `<!-- covers: -->`
line, comma-separated, and `featuremap check` fails when an id has no recipe or a
recipe covers an id that no longer exists.

## Preconditions

- **Base URL:** `B=https://ochk.io/docs`, or `http://localhost:$PORT/docs` for a
  local build (see `../SKILL.md`).
- **Nothing to sign in to:** the docs are public and read-only. No form, wallet or
  account.
- **Never driven:** none needed. The docs send nothing anywhere but analytics, which
  the search recipe answers locally.

## Proof rules

- Drive the URL a reader uses, under `/docs`. A page that answers only without the
  prefix is broken.
- A recipe lists every entry point (the page, its old docs.ochk.io address, a moved
  path). Proving one does not prove the others.
- A changed page is proven by its live text, not by a 200: a stale deploy answers
  200 too.
- An unreachable entry point is reported with its missing precondition. It is not
  counted as verified.

## Areas

- [guides](guides.md): the six verbs and OC Chat: attest, lock, vote, stamp, agent,
  pledge, chat.
- [products](products.md): ochk.app (`/me`), vault, cosign, Connect, the federation
  charter and the docs charter.
- [reference](reference.md): the home page, getting started, ecosystem, reference,
  integration, infrastructure and the OpenAPI references.
- [sdk](sdk.md): the generated TypeDoc reference under `/sdk`.
- [search](search.md): the search dialog.
- [site](site.md): docs.ochk.io's 308s, moved pages, SDK aliases, `/api/og`, `/404`,
  `/500`.
- [unknown-api](unknown-api.md): the JSON 404 for any `/api` address the site does not serve.

## Entry contract

Each area file has: an H1, a one-line summary, a `<!-- covers: ids -->` line, then
exactly these sections: `## Sub-features`, `## How to reach it`, `## How to check it`,
`## Gotchas`. Keep it short enough to run without reading source.
