# OC-Me Federation v1 — Charter

> **Status: draft. No federation runs under this charter.**
> [`/api/federations`](https://me.ochk.io/api/federations) lists `oc-me-v1` as
> recruiting, with no guardian seats and no charter hash on its record. While
> ochk.app is in testing, OrangeCheck holds every user's accrued balance. Read
> this page as the text a v1 guardian set would sign, not as a description of
> today. [Federation custody](/me/federation) has the present tense.

**Charter text v1.1.0 · draft, 2026-10-31.** It supersedes v1.0.0 (2026-05-12),
kept [below](#superseded-v100) as signed history.

This is the charter for the Fedimint federation designed to hold
[`ochk.app`](https://ochk.app) balances. Each guardian operator would sign the
SHA-256 of this document's canonical bytes (the
[Canonical bytes](#canonical-bytes) section below) with a hardware-backed
Ed25519 operator key. Those signatures would appear on
[ochk.app/me/operator/ceremonies](https://ochk.app/me/operator/ceremonies) and
the per-federation view at
[ochk.app/federations/oc-me-v1](https://ochk.app/federations/oc-me-v1).

This charter binds the **federation**, not OrangeCheck the company. OC operates
under the [company-wide charter](/charter); this document is downstream of it
and may not contradict it.

## 1. Identity

- **Federation slug:** `oc-me-v1`
- **Federation name:** OC-Me Federation v1
- **Threshold:** `3-of-4` · any 3 of 4 guardian seats authorize a Bitcoin
  transaction; fewer than 3 cannot.
- **Target guardian count:** 4.
- **Ratification version:** `v1.1.0` (draft).
- **Client:** orangecheck's executor, with its own Fedimint client. ochk.app has
  none.

## 2. Custody promise

The OC-Me Federation v1 is M-of-N (3-of-4). Any 3 guardians colluding can move
funds; fewer than 3 cannot. The threshold is strictly greater than ⌊N/2⌋ so no
minority can defraud users.

OrangeCheck (the company) holds zero key shares and is not a guardian. OC is a
**client** of this federation, never an operator of it. Users hold no Fedimint
wallet of their own: orangecheck's executor holds each user's claim as ecash in
the federation until it pays the user out (§6).

## 3. Guardian operator disclosure

The load-bearing operational-independence invariant is **operator-key
diversity** — each seat is controlled by a distinct hardware-backed Ed25519
operator key, held by a distinct legal entity, ideally in a distinct legal
jurisdiction. Vendor diversity is not a §1.3 conformance test (Fedimint
threshold-signing prevents any single vendor from moving funds regardless of who
hosts the daemons).

Each guardian operator publishes:

- their hardware-backed operator pubkey fingerprint
- the legal entity operating their seat
- a public security-disclosure contact
- any conflicts of interest

These disclosures appear on [ochk.app/trust](https://ochk.app/trust#numbers)
(the marketplace) and on the per-federation deep-view.

## 4. OrangeCheck's role

OrangeCheck the company is a **client** of this federation, not a guardian. OC
holds zero key shares and cannot reach the threshold by itself, alone or with
any subset of guardians the company has not formally accepted into the operator
program. The company never asks operators to sign envelopes on its behalf, and
the operator portal (`ochk.app/me/operator`) is incapable of producing operator
signatures — every state-changing action requires the operator's hardware-key
signature, which the portal cannot forge.

## 5. Lightning gateway disclosure

The federation registers at least one Lightning gateway operated by a
non-OrangeCheck party. The gateway disclosure (operator, fee schedule, uptime
SLA) is published per-instance and rotates as the federation's gateway
relationships change. The current registry lives on the per-federation
deep-view.

## 6. Exit clause

> **New in v1.1.0 (2026-10-31), to match what is built.** v1.0.0 promised a
> recovery from a mnemonic saved at `/me/wallet` and an export from a Fedimint
> client in the browser. Neither exists: ochk.app has no Fedimint client, and no
> user holds a mnemonic.

orangecheck's executor holds each user's claim as ecash in the federation until
it pays the user out. A user leaves by:

- **(a)** a payout to a Lightning wallet they choose. The executor pays it from
  the ecash it holds; a gateway only routes the payment.
- **(b)** following a successor federation: when this one is replaced, the
  executor moves the float it holds to the successor.

Both paths run through orangecheck's executor. A way out that works with
OrangeCheck offline, such as users holding their own ecash in an external
Fedimint wallet, is not built.
[What if OC sunsets?](/me/federation#what-if-oc-sunsets) says what that means
today.

## 7. Dispute resolution

Users with complaints about the federation's operation contact
[`abuse@ochk.io`](mailto:abuse@ochk.io) (the company's published abuse address)
and the guardian operator listed for their issue (jurisdictional / operational
disputes route to the specific guardian). OrangeCheck reviews abuse reports and,
where appropriate, requests the guardian operator address them. Disputes the
operator and OC cannot resolve escalate to the federation's charter-amendment
process (§8) or to legal counsel.

## 8. Charter amendment process

This charter is amended by every seated guardian signing the new version with
their hardware-backed operator keys, the same rule as ratification. The new
SHA-256 hash replaces the prior version at this URL and on the federation
registry. Users are notified via:

- the [ochk.app/changelog](https://ochk.app/changelog) entry
- per-user [alerts on ochk.app](https://ochk.app/me/activity?alerts=open)
- the operator [incidents feed](https://ochk.app/me/operator/incidents)

Amendments that materially change the federation's operational posture
(threshold, target guardian count, fee structure, exit clause) require the
amendment to publish at least 14 days before activation.

## Canonical bytes

The SHA-256 of the following canonical bytes is the federation's charter hash.
Operators sign this hash with their hardware-backed Ed25519 key; the signature
is the ratification. Every guardian signs v1.1.0 before their seat counts.

```
# OC-Me Federation Charter v1.1.0 · canonical bytes
version: v1.1.0
federation_slug: oc-me-v1
name: OC-Me Federation v1
threshold: 3-of-4
target_guardian_count: 4
oc_residual_bps: 0
bootstrap_mode: false
canonical_url: https://docs.ochk.io/federation/oc-me-v1
drafted_at: 2026-10-31T00:00:00Z
supersedes: v1.0.0 58f5ac7832e1854caf5f66e63459be2b6889661c0136cea51267d9e1ea72d4e8
## commitments
threshold > floor(N/2): true
oc_is_a_guardian: false
oc_residual_pct: 0
exit_clause: a payout to a Lightning wallet the user chooses, or a move to a successor federation; both run through orangecheck's executor, and no exit works with OrangeCheck offline
operator_key_diversity: distinct hardware-backed Ed25519 operator pubkey per seat
amendment_quorum: every seated guardian
amendment_notice_days: 14
```

The canonical bytes are the EXACT UTF-8 bytes of the block between the fenced
code blocks above. Newlines are LF (`\n`). The block starts with
`# OC-Me Federation Charter v1.1.0 · canonical bytes\n` and ends with the last
commitment line followed by a single trailing `\n`. Its SHA-256 is
`5fcb29717a3908c89024ed8ed507888cb069496f171eb233a9a4179ec9ec5f50`.

A consumer verifying offline:

1. Copies the v1.1.0 canonical bytes block above into a file.
2. Computes `sha256(file)` and checks it is the v1.1.0 hash above.
3. Compares it with `meta.charter_hash` at
   [me.ochk.io/api/operator/charter?federation=oc-me-v1](https://me.ochk.io/api/operator/charter?federation=oc-me-v1).
   If that still names v1.0.0, check the superseded block below the same way.
4. Verifies each operator's `sig_hex` (returned in the same JSON) against their
   `operator_pubkey` and the hash using Ed25519.

The kit ships this verification as `oc-guardian charter fetch oc-me-v1` (see
[`oc-guardian-kit/BYPASS.md`](https://github.com/orangecheck/oc-guardian-kit/blob/main/BYPASS.md)
§06).

## Superseded: v1.0.0

v1.0.0 is kept byte for byte as signed history. One operator signed it on
2026-05-21 (`op-cf6d365829055b25`); no federation was seated under it. It is
superseded because its exit clause, an on-chain withdrawal by every user through
a threshold-signed transaction, describes a path that was never built. Its
amendment quorum, 4 of 5 operators, also cannot be met with 4 seats. Its SHA-256
is `58f5ac7832e1854caf5f66e63459be2b6889661c0136cea51267d9e1ea72d4e8`.
