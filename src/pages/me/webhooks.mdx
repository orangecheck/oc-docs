# ochk.app · Webhooks

**Every event your project records is delivered to your registered endpoints as
its receipt, signed with me.ochk.io's Ed25519 webhook key.** Verify the
signature against the **raw** request body — frameworks that re-serialize before
your handler will produce a different byte sequence and the signature will not
validate.

The key set is at
[`https://me.ochk.io/api/dev-jwks`](https://me.ochk.io/api/dev-jwks) (the path
is historical; it is the production key). It is **not** the sign-in key set at
`ochk.io/.well-known/jwks.json`: that one signs session tokens, and a webhook
checked against it always fails with an unknown `kid`. Both SDKs fetch the right
one and cache it for an hour.

## Reception · Node + Express

```ts
import { oc } from '@orangecheck/me-client';
import express from 'express';

const app = express();
app.use(express.text({ type: 'application/json' })); // raw body!

app.post('/api/oc/webhook', async (req, res) => {
    const result = await oc.webhook.verify(
        req.body,
        req.header('OC-Signature'),
        req.header('OC-Key-Id')
    );
    if (!result.ok) return res.status(401).end(result.reason);

    const envelope = JSON.parse(req.body);
    // envelope.kind === 'oc-billable-event'
    // envelope.subtype === 'session_creation' | 'payment_authorization' | …
    // envelope.id is content-addressed — idempotent
    await onOcEvent(envelope);
    res.status(200).end();
});
```

## Reception · Python

`orangecheck` 2.3 or later (`pip install orangecheck`). `verify_webhook` takes
the request headers and the raw body, and returns the parsed event or raises
`InvalidWebhook` with a one-word `reason`.

```python
from fastapi import FastAPI, HTTPException, Request
from orangecheck import InvalidWebhook, verify_webhook

app = FastAPI()
seen: set[str] = set()  # use your database in production

@app.post("/api/oc/webhook")
async def oc_webhook(request: Request):
    raw = await request.body()  # the bytes as sent, never the parsed JSON
    try:
        event = verify_webhook(request.headers, raw)
    except InvalidWebhook as err:
        raise HTTPException(401, err.reason)
    if event["id"] in seen:  # deliveries can repeat
        return {}
    seen.add(event["id"])
    on_oc_event(event)
    return {}
```

In Flask, pass `request.headers` and `request.get_data()`; in Django,
`request.headers` and `request.body`.

## Reception · Rust + Axum

```rust
use axum::{extract::State, http::StatusCode, response::IntoResponse};
use ed25519_dalek::{Signature, Verifier, VerifyingKey};

async fn webhook(
    State(pub_key): State<VerifyingKey>,
    headers: axum::http::HeaderMap,
    body: bytes::Bytes,
) -> impl IntoResponse {
    let sig_hex = headers.get("OC-Signature").and_then(|v| v.to_str().ok()).unwrap_or("");
    let sig_bytes = hex::decode(sig_hex).unwrap_or_default();
    let Ok(sig) = Signature::from_slice(&sig_bytes) else {
        return StatusCode::UNAUTHORIZED;
    };
    if pub_key.verify(&body, &sig).is_err() {
        return StatusCode::UNAUTHORIZED;
    }
    let envelope: serde_json::Value = serde_json::from_slice(&body).unwrap();
    process_event(envelope).await;
    StatusCode::OK
}
```

## Headers OC sends

| Header                | Meaning                                                                         |
| --------------------- | ------------------------------------------------------------------------------- |
| `OC-Signature`        | Ed25519 signature, hex-encoded, computed over the raw body                      |
| `OC-Key-Id`           | `kid` of the OC public JWK that signed the event                                |
| `OC-Envelope-Id`      | Idempotency key — same envelope retried after 2xx ack is your problem to dedupe |
| `OC-Subtype`          | Event subtype, copied for routing convenience                                   |
| `OC-Class`            | A · B · C: One-time, Per action, Per session · `system` for project notices     |
| `OC-Delivery-Attempt` | 1-based attempt counter, updated on each retry (the signature is unchanged)     |
| `Content-Type`        | `application/json`                                                              |

## What the body carries

A billable event arrives as the event itself plus three fields:

| Field              | Meaning                                                                                                                           |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `kind`             | `oc-billable-event`                                                                                                               |
| `sub`              | The person, as a pairwise id for your project only. It is not their `did_oc`; the response to the event you fired carries it too. |
| `scopes`           | Fields the person agreed to share with you, when there are any                                                                    |
| `id`, `subtype`, … | The event: `id`, `occurred_at`, `class`, `subtype`, `site`, the fee split, `context`, `verify_url`                                |

A project notice (`OC-Class: system`) is
`{ kind: 'oc-system-event', subtype, project_key, … }` and names no person.

## Delivery semantics

|                    |                                                                                                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Guarantee**      | At-least-once. Deduplicate on `OC-Envelope-Id` (the event's `id`). The signature has no timestamp, so deduplication is also your replay protection.                      |
| **Ack**            | Any 2xx within 8 seconds. A redirect is not followed or retried: register the final URL.                                                                                 |
| **Retry schedule** | 6 attempts: at once, then 30 s, 5 min, 30 min, 2 h and 12 h after each failure. Retries are picked up by an hourly sweep, so each can run up to an hour after it is due. |
| **After that**     | The delivery is dead-lettered and listed with your webhooks, where you can requeue it. The endpoint is not muted, and the event stays at `/api/envelope/[id]`.           |

## The raw-body trap

> **Verify against the raw bytes, not the parsed JSON.**

`JSON.parse(body)` then `JSON.stringify(value)` produces a _different byte
sequence_ — different key order, different whitespace, different number
formatting. The signature is computed over the original bytes; re-serialized
bytes will not match.

| Framework             | The fix                                                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **Express**           | `app.use(express.text({ type: '*/*' }))` — accept body as a raw string.                                            |
| **Next.js Pages API** | `export const config = { api: { bodyParser: false } }` — disable body parsing, then read the stream into a Buffer. |
| **Fastify**           | Use a `preParsing` hook to capture the raw body before parsing.                                                    |
| **Hono**              | `c.req.text()` to get the raw string.                                                                              |
| **Rust + Axum**       | `body: bytes::Bytes` extractor, never `Json<…>`.                                                                   |

## Test with a real delivery

On your project, **Send a test event** fires a sample event under your project
key. It is stored with your project's events and delivered to every webhook you
registered, signed like any other delivery, so your receiver should accept it.
Deliveries that run out of retries are listed with your webhooks, where you can
requeue them.

## Handler patterns we recommend

```ts
// Idempotency · keep a small cache of recently seen envelope ids.
const seen = new LRU<string, true>({ max: 10_000 });

app.post('/api/oc/webhook', async (req, res) => {
    const result = await oc.webhook.verify(
        req.body,
        req.header('OC-Signature'),
        req.header('OC-Key-Id')
    );
    if (!result.ok) return res.status(401).end(result.reason);

    const envelope = JSON.parse(req.body);
    if (seen.has(envelope.id)) return res.status(200).end(); // already processed
    seen.set(envelope.id, true);

    try {
        await onOcEvent(envelope);
        res.status(200).end();
    } catch (err) {
        // Don't 5xx unless you actually want the retry; otherwise log + 200.
        console.error(err);
        res.status(500).end();
    }
});
```
