# ochk.app · Operator Runbook

**Run the guardian binary on hardware you control.**

The portal handles your operator-key custody and every state-changing envelope
(apply, charter-sign, incident-publish, etc.). The guardian **binary** — the
process that participates in DKG and threshold-signing with the rest of the
federation — has to run on a host with a stable network address. This page is
the runbook for that piece.

The operator program is not open, and there are no guardian seats yet: while the
system is in testing, orangecheck holds every role
([ochk.app/custody](https://ochk.app/custody)). This runbook describes how a
seat is run.

If you'd rather not manage a host, the
[hosted-hardware option](https://ochk.app/me/operator) on the dashboard lets
orangecheck run the binary on its hardware. Your operator key still stays in
your browser or kit, but a hosted guardian is only as independent as
orangecheck, which runs the machine.

## Prerequisites

- An operator key provisioned at
  [ochk.app/me/operator](https://ochk.app/me/operator) (or via
  `oc-guardian init` on the kit). You'll need the **public** half for the
  guardian's settings.
- An accepted application — your operator_id appears in the registry at
  [/api/operator/registry](https://me.ochk.io/api/operator/registry).
- A federation membership — your operator key has signed at least one
  federation's charter at
  [/me/operator/ceremonies](https://ochk.app/me/operator/ceremonies).
- A host. Linux, kernel ≥ 5.15, x86_64 (the image is linux/amd64 only). 4 GB RAM
  minimum (8 GB recommended). 80 GB SSD. Reachable on a stable IP, ideally with
  a DNS name. Ports 9000/tcp and 9001/tcp open to federation peers (the
  federation directory tells you the peer list).

## 01 · Settings

The guardian reads its settings from the environment; there is no config file.
Put them in an env file on the host, say `/etc/oc-guardian/guardian.env`:

```bash
# /etc/oc-guardian/guardian.env: one setting per line, comments on their own line
OC_OPERATOR_ID=op-<your-id>
OC_OPERATOR_PUBKEY_HEX=<64 hex chars>
OC_FEDERATION_SLUG=<federation slug>
# bitcoin, testnet, testnet4, signet or regtest; there is no default
OC_BITCOIN_NETWORK=bitcoin
# or OC_BITCOIND_URL, OC_BITCOIND_USERNAME and OC_BITCOIND_PASSWORD
OC_ESPLORA_URL=<esplora url>
OC_PUBLIC_HOST=<the name peers reach this host at>
# keeps setup closed to other machines until DKG is done
OC_GUARDIAN_SETUP_PASSWORD=<a password>
OC_ATTESTATION_POST_URL=https://me.ochk.io/api/operator/attestation
```

**No private key in these settings.** Your operator key signs the program's
envelopes in your browser or kit. `fedimintd` signs for the federation with its
own key share, which it keeps in its data directory. Until DKG has run, whoever
reaches the setup API first sets the guardian's password, so set
`OC_GUARDIAN_SETUP_PASSWORD`, or bind the API to 127.0.0.1 until DKG is done.
Every setting is listed in the
[kit's README](https://github.com/orangecheck/oc-guardian-kit#running-fedimintd).

## 02 · Pull the signed image

The guardian is shipped as a linux/amd64 Docker image (debian:bookworm-slim,
with a pinned, hash-checked `fedimintd`). Verify its cosign signature before
running. The release archives, not the image, also carry SLSA build provenance
(`gh attestation verify`).

```bash
docker pull ghcr.io/orangecheck/oc-guardian:latest

cosign verify ghcr.io/orangecheck/oc-guardian:latest \
  --certificate-identity-regexp 'https://github.com/orangecheck/oc-guardian-kit' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

If verify fails, abort. The binary signing identity is the oc-guardian-kit
GitHub Actions runner; anything else is a tampered image.

## 03 · Run

Pass the settings in and keep `/data` on a volume. Bind 9000 (P2P) and 9001
(API) to the host's public interface (or behind a reverse proxy that terminates
TLS).

```bash
docker run -d --name oc-guardian --restart unless-stopped \
  --env-file /etc/oc-guardian/guardian.env \
  -v oc-guardian-data:/data \
  -p 9000:9000 \
  -p 9001:9001 \
  ghcr.io/orangecheck/oc-guardian:latest
```

The image runs `oc-guardian fedimintd run`, which starts `fedimintd`, restarts
it if it stops, and sends liveness reports. The container needs **no** operator
key to run. `fedimintd` keeps its data in `/data/fedimintd`; keep that volume
across upgrades.

## 04 · Confirm health

With `OC_ATTESTATION_POST_URL` set, the guardian posts a signed liveness report
there every 300 seconds, when it has a key to sign with: your operator key, if
the kit on that machine holds it, or a delegated attestation key
(`OC_ATTEST_KEY_HEX`). Without one it runs but sends no report. Once reports
arrive, [/me/operator/guardians](https://ochk.app/me/operator/guardians) shows
**Signed heartbeat, current**.

You can also check locally:

```bash
docker exec oc-guardian oc-guardian fedimintd status
```

It shows `fedimintd`'s status and setup phase.

## 05 · Upgrades

Each kit release publishes a new signed image, tagged with the release and
`latest`. To upgrade:

```bash
docker pull ghcr.io/orangecheck/oc-guardian:latest

# verify the new image (same cosign command as step 02)

docker stop oc-guardian
docker rm oc-guardian

# re-run step 03 (the new image)
```

Your guardian is offline during the swap. Coordinate via the federation channel
so multiple guardians don't upgrade at the same time.

## 06 · Leaving or replacing a guardian

Until a key ceremony completes, the roster can still change, and a guardian who
exits frees the seat for a replacement. After it completes, the seat roster is
locked, a ceremony reset included: every guardian holds a key share bound to it.
A guardian then leaves by an exit, and the trust posture keeps counting the
share it still holds. A failed guardian is replaced by moving to a successor
federation.

## Troubleshooting

| Symptom                                                | Likely cause                                                                | Fix                                                                      |
| ------------------------------------------------------ | --------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| no signed heartbeat on `/me/operator/guardians`        | `OC_ATTESTATION_POST_URL` unset, or no key on the host to sign reports with | set the URL; keep the operator key on the host or delegate a key         |
| **Signed heartbeat, stale**                            | reports stopped, or the guardian cannot reach `me.ochk.io`                  | check the container is running; check egress firewall                    |
| federation peers cannot reach you                      | port 9000/9001 not open                                                     | check ingress firewall + DNS                                             |
| `fedimintd run` refuses to start a guardian before DKG | its setup API or UI can be reached from other machines                      | set `OC_GUARDIAN_SETUP_PASSWORD`, or bind the API to 127.0.0.1 until DKG |
| the guardian exits at start, naming a setting          | a required setting is unset                                                 | set it (step 01)                                                         |
