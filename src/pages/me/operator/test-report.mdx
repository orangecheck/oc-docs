# ochk.app · Operator suite test report

> **Draft, not final.** One step, C07 (moving a running federation to its
> successor), is half done: its first sitting passed on 2026-10-27, and its
> second can run from 2026-11-10 04:20 UTC. This page changes when it closes.

**What this is.** A federation run end to end through ochk.app: operators take
seats, four guardians run on hosted machines, a key ceremony runs through the
portal, a gateway is funded, and orangecheck's executor settles top-ups and
payouts through it. Each step runs twice: as a script against the API, and in a
browser on the app, with screenshots at 1440 and 390 pixels wide. A step passes
only when both do.

**What it is not.**

- **Test coins only.** Everything ran on mutinynet, a public test signet.
  Nothing here moved real value.
- **Not operator independence.** Every operator identity in this test is held by
  orangecheck. It tests the machinery with distinct keys and machines. The
  federation's trust tier stays bootstrap.
- **Not a separate product.** It is the same code as ochk.app and its API, run
  on an isolated test deployment with its own databases and keys. Production
  never sees the test federation.

## The federation under test

- `oc-mutiny-v1`: four guardians, threshold 3 of 4, on mutinynet, live since
  2026-10-22. The guardians run fedimintd 0.11.4 on hosted machines in four
  regions (Frankfurt, Ashburn, Singapore, São Paulo).
- Charter signed by all four seats; key ceremony run through the portal.
- One Lightning gateway (gatewayd 0.11.4, LDK) funded on mutinynet.
- orangecheck's executor, at the same commit production's executor runs, holds
  the float and signs every settlement.

## Limits this run found

The second is true today. The first and third were fixed the same day.

1. **Fedimint Lightning addresses could not be paid out to.** During this run
   the executor paid a Lightning address only when its invoice committed to the
   address's metadata (LUD-06). Upstream Fedimint's own Lightning address server
   issues invoices that do not, so payouts to a Fedimint-backed Lightning
   address were refused. The test's own wallet was built to commit to its
   metadata. Relaxed on 2026-10-26: an invoice with no description hash is
   accepted when the address's own host serves it, and one that carries a hash
   must still match. C11, above, paid such an invoice.
2. **With one guardian down, a payment in can need a second try.** Before it
   accepts an incoming payment, the gateway (gatewayd 0.11.4) asks the
   federation for its block count and gives up after 10 seconds. With only three
   guardians up, they did not always answer in time, and the payment failed back
   to the payer. Paid again, it settled. C05 ran twice on 2026-10-26: in the
   first run the first attempt was refused this way; in the passing run the
   top-up settled on its first attempt.
3. **A project's limit of three open top-ups counted paid ones.** During this
   run each top-up invoice counted toward the limit until 15 minutes after it
   expired, paid or not, so a fourth top-up within about an hour was refused.
   Fixed on 2026-10-26: a credited top-up no longer counts, and an unpaid one
   still counts until it lapses.

## C07: moving to a successor

Guardians are fixed at a federation's key ceremony, so when an operator leaves,
the federation moves to a successor with the new operator in the seat. The move
gives integrators 14 days' notice before the switch, so C07 runs in two
sittings, two weeks apart.

**First sitting, 2026-10-26 to 2026-10-27: passed.** On the test stack, over
several deploys of the code then on `main`. Each part names what it ran on: the
API (oc-me-web), the app (oc-app-web) and the executor (oc-me-web).

- Before the sitting, O4 filed an exit naming O5 as successor, and O1 to O3
  ratified it.
- On 2026-10-26, C07's first start created the successor, `oc-mutiny-v2` (see
  the end of this section).
- On 2026-10-27, with the API at `e3274060`, the app at `630e563` and the
  executor at `2fc3a6fd`: `oc-mutiny-v2` ran its key ceremony on four new
  guardians in the same four regions. Its settlement key is the executor's, and
  `oc-mutiny-v1`'s gateway also serves it.
- With the API at `2280312b`, the app at `a90e41e` and the executor at
  `2fc3a6fd`: all four of `oc-mutiny-v2`'s guardians list the gateway. The owner
  froze `oc-mutiny-v1` and its one integrator was told. `oc-mutiny-v1`'s
  guardians voted the successor into the federation's own metadata, where anyone
  holding its ecash can read it.
- With the API at `2280312b`, the app at `a90e41e` and the executor at
  `b8c55f05`: the portal recorded the successor. Payouts paused, the drain was
  recorded, and the executor moved the float to `oc-mutiny-v2` on its own, in
  five on-chain batches over 13 minutes.
- Every sat is accounted for: 227,797 sats in `oc-mutiny-v1` before = 220,028
  credited in `oc-mutiny-v2` + 2,748 on-chain fees + 5,020 mint fees + 1 sat
  left behind. Unexplained: 0.
- The executor switched itself to `oc-mutiny-v2` and reported in.
- With the API at `2280312b` and the app at `a90e41e`: the switch waits out the
  notice. The app shows it disabled until 2026-11-10 04:20 UTC, and a switch
  sent straight to the API is refused and changes nothing.

**What the sitting found.** Four faults each stopped it once. All four were
fixed on 2026-10-27, and the sitting carried on:

- The key ceremony page hid a failed setup-code exchange, so every guardian
  looked ready. It now shows the error and names the guardians it waits on.
- Listing the gateway asked no guardian, because the portal's record of a hosted
  machine did not follow the machine once it started. The portal now checks the
  machine itself.
- After that fix, listing the gateway still reached none of the successor's
  guardians: it looked for their credentials only where key ceremonies kept them
  before 2026-10-23. It now finds them the way the ceremony does.
- The executor missed the successor in the federation's metadata, which
  fedimint-cli 0.11.4 returns in a shape it did not read. It now reads that
  shape and logs any skip. The test stack's executor runs the fix; production's,
  which is moving no federation, takes it with its next update.

**Still open.**

- The second sitting, from 2026-11-10 04:20 UTC: the switch, moving the
  projects, resuming payouts, a top-up and a payout on `oc-mutiny-v2`, and
  retiring `oc-mutiny-v1`.
- Two safety checks have not run on the test stack: halting the move part-way,
  and restarting the executor while a batch is in transit. In the first sitting
  the executor reported the move only once it had finished, so the run never saw
  it in progress; it now reports each batch as it goes. Both checks were proven
  on regtest on 2026-10-27, within stated limits: the portal ran locally, the
  executor's regular report to it was a stand-in, the halt was set directly, and
  the restart followed a forced kill of the executor. The live drill runs on the
  test stack from 2026-11-10.

C07 was first started on 2026-10-26, by mistake, during a rerun of the other
steps. It created the successor federation, `oc-mutiny-v2`, with no machines
hosted and no money moved, and stopped. The sitting carried on from that
federation.
