# orangecheck · Quickstart

Two tracks, four steps each. **Sign in** is free and stands on its own: at the
end of it, your app signs people in and can keep bots out. **Pay your users** is
optional, and you can add it whenever you like. Nothing here needs a sales call,
and nothing is destructive.

## Track 1 · Sign in (free)

### 1 · create a project

Sign in at [ochk.app](https://ochk.app/me/projects/new) with the account you
already have. Your orangecheck account is your developer account. The new
project asks for your app's name and domain, how people sign in (choose **Use
orangecheck sign-in**), and whether to pay your users. Leave that at **Not
now**; track 2 turns it on.

```text
name:    Your App
domain:  yourapp.example
→ project key: pk_test_a4f9k2x…
```

A new project starts in test mode, so its key starts `pk_test_`.

### 2 · add the sign-in popup

```bash
yarn add @orangecheck/me-client
```

Call `signInWithOc()` inside a click handler, or the browser blocks the popup.
The person signs in on orangecheck's page with email, Google, GitHub or a
Bitcoin wallet, and the popup hands your page a token bound to your origin.

```ts
import { signInWithOc } from '@orangecheck/me-client/popup';

document.querySelector('#signin')!.addEventListener('click', async () => {
    const result = await signInWithOc();
    if (!result) return; // closed, or the popup was blocked
    const me = await fetch('/api/auth/me', {
        headers: { Authorization: `Bearer ${result.token}` },
    });
    if (me.ok) location.assign('/dashboard');
});
```

orangecheck's own cookie never reaches your site, so the token is how your
backend learns who signed in. Send it as a Bearer, or trade it once for your own
cookie: the per-framework code on your project's page does that, with your
project key filled in.

`<OcSignIn>` from `@orangecheck/auth-client` mounts the sign-in form in your own
page instead of a popup. It works only on orangecheck's own sites (`*.ochk.io`
and ochk.app), which share orangecheck's session. Everywhere else, use the
popup.

### 3 · verify the session on your server

```ts
// Next.js Pages · pages/api/auth/me.ts
import { withOcAuth } from '@orangecheck/me-client/server';

export default withOcAuth(
    async (req, res) => {
        if (!req.ocSession) return res.status(401).json({ ok: false });
        res.status(200).json({
            ok: true,
            account: {
                id: req.ocSession.sub,
                did_oc: req.ocSession.did_oc,
                display_name: req.ocSession.name ?? null,
            },
        });
    },
    { audience: 'https://yourapp.example', projectKey: 'pk_test_a4f9k2x' }
);
```

Express:

```ts
import { ocAuthExpress } from '@orangecheck/me-client/server';

app.use(
    ocAuthExpress({
        audience: 'https://yourapp.example',
        projectKey: 'pk_test_a4f9k2x',
    })
);
```

Hono, Workers, Bun, Deno:

```ts
import { ocAuthHono } from '@orangecheck/me-client/server';

app.use(
    '*',
    ocAuthHono({
        audience: 'https://yourapp.example',
        projectKey: 'pk_test_a4f9k2x',
    })
);
```

`audience` is your own origin: a token issued to any other site is refused.
`projectKey` makes the wrapper enforce who can sign in (step 4) from your
project's settings. The wrapper fetches and caches orangecheck's keys itself, so
there are no env vars and no JWKs to handle. `did_oc` is the person's account
id, the same in every app.

### 4 · choose who can sign in

On your project, under **Who can sign in**:

| Choice                 | Who gets in                                                              |
| ---------------------- | ------------------------------------------------------------------------ |
| **Everyone** (default) | every orangecheck account                                                |
| **Backed by bitcoin**  | accounts backed by one coin of **at least N sats, held at least D days** |

The coin stays in the person's wallet, and you never see it. A change is
enforced within a minute. An account below the bar gets `403 bond_required` with
a `back_url`, where the person can back their account. Details, and how to keep
one account per coin: [Who can sign in](/me/require-bond).

That is sign-in. It costs nothing, in test mode or live.

## Track 2 · Pay your users (optional)

### 1 · choose when you pay

On your project, under **Pay your users**: **Off** (the default), **Always**, or
**Promos**, each a named stretch with a start and an end. Outside a pay period
an event earns nothing, costs nothing and leaves no record, so firing events
from code that runs all the time is safe. Details:
[Paying your users](/me/paying-users).

### 2 · set what each event earns

For each event, set what your user earns: a fixed number of sats, or a share of
a payment. You pay that divided by 0.8, the 20% fee included.

| Event              | Group       | Your user earns | You pay    |
| ------------------ | ----------- | --------------- | ---------- |
| `account_creation` | One-time    | 1,000 sats      | 1,250 sats |
| `stamp_signing`    | Per action  | 80 sats         | 100 sats   |
| `session_creation` | Per session | 40 sats         | 50 sats    |

Add your own events too, under any key you choose (`lesson_completed`, say). Try
numbers first in the [sandbox](https://ochk.app/integrate/sandbox). In the
config (`IntegratorPriceConfig`) a price is `site_pays`, and what your user
earns is `user_share_pct` of it.

### 3 · fire events from your server

```ts
import { oc } from '@orangecheck/me-client';

const res = await oc.event.fire({
    project_key: 'pk_test_a4f9k2x',
    subtype: 'account_creation',
    signingSecret: process.env.OC_SIGNING_SECRET,
    userAddress: didOc, // who earns: req.ocSession.did_oc from step 3 above
});
if (!res.earned) {
    // not paying now: nothing recorded or charged
}
```

Fire from your backend, never the browser. The signing secret, on your project's
keys page, proves the call comes from your project. Every paid event gets a
receipt anyone can check offline against Bitcoin: see
[an example receipt](https://ochk.app/verify/example).

### 4 · send a test event

On your project, **Send a test event** fires a sample event under your project
key through the same pipeline as a real one. It is stored with your project's
events, delivered to your [webhooks](/me/webhooks), and gets a receipt you can
open. It records whether or not you are paying now.

### Going live

Test mode records and splits events, but no real sats move. Live mode needs a
verified domain, a balance while you pay your users, and settlement open for
every project. Paying is in testing: until settlement opens, no real sats move,
and your project's page shows when that changes.

To verify your domain, add either record, then check it from your project:

```text
# DNS TXT at yourapp.example (apex)
oc-verify=<token>

# OR a meta tag in <head> at https://yourapp.example/
<meta name="oc-domain-verify" content="<token>" />
```
