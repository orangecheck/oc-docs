# integration

Concrete snippets for gating your community, DAO, forum, or app on an OC Vote
poll. Every example uses
[`@orangecheck/vote-core`](https://npmjs.com/package/@orangecheck/vote-core) +
[`@orangecheck/vote-cli`](https://npmjs.com/package/@orangecheck/vote-cli) + the
curl-friendly `/api/tally` endpoint.

## fork-ready templates

Three copy-forkable integrations live at
[**`orangecheck/oc-vote-examples`**](https://github.com/orangecheck/oc-vote-examples):

- [**Discord bot**](https://github.com/orangecheck/oc-vote-examples/tree/main/discord-bot)
  — `/poll <id>` + `/poll-watch <id>` slash commands that render tallies as
  embeds with bar charts. Stateless. ~200 lines of discord.js.
- [**GitHub Action gate**](https://github.com/orangecheck/oc-vote-examples/tree/main/github-action-gate)
  — `uses: orangecheck/oc-vote-examples/github-action-gate@main`. Gates a job on
  a poll's tally via a configurable jq expression. Outputs `state` + `passed` +
  `tally-json`.
- [**Shell recipes**](https://github.com/orangecheck/oc-vote-examples/tree/main/shell)
  — one-liner deploy-gates, create/vote/reveal flows, cron pollers, discovery —
  pure bash + `npx @orangecheck/vote-cli`.

Fork, swap the placeholder poll id / Discord token / whatever, ship. Nothing in
those templates is load-bearing for the protocol; they're UI patterns on top of
the same `/api/tally` endpoint this page describes.

## check a tally result server-side

You've shipped a poll. You want your backend (Discord bot, forum moderator, DAO
executor) to read the tally and act.

```ts
// anywhere in Node 20+
const pollId =
    '9825268c74a3a15baefe8f9705f774cc7bb97205922fc828df3b377e0e158a18';
const res = await fetch(`https://vote.ochk.io/api/tally?poll=${pollId}`);
if (!res.ok) throw new Error(`tally: HTTP ${res.status}`); // 400 bad id, 404 not found
const tally = (await res.json()) as {
    state: string;
    tallies?: Record<string, number>;
};

if (tally.state !== 'tallied' || !tally.tallies)
    throw new Error('poll not ready');
const top = Object.entries(tally.tallies).sort((a, b) => b[1] - a[1])[0];
// top = [optionId, weight], e.g. ['yes', 12311]
```

The endpoint is cached 60s at the edge and verifies every BIP-322 signature
before returning. For higher-value decisions, **verify independently** with the
CLI — see below.

## independent verification (the right way for high-value decisions)

```bash
npx -y @orangecheck/vote-cli tally <poll_id> --json
```

The package's command is `oc-vote`: after `npm i -g @orangecheck/vote-cli`,
`oc-vote tally <poll_id> --json` is the same.

The CLI pulls the poll + ballots from Nostr (`--relay` to pick relays), verifies
every BIP-322 signature with `@orangecheck/bip322`, reads the UTXOs confirmed by
the snapshot block from an Esplora API (`--mempool-base`, default
mempool.space), and runs the pure tally function. Like `/api/tally`, it counts
coins that are still unspent, so a coin spent after the snapshot drops out. If
the JSON `snapshot_block`, `turnout` and `tallies` match vote.ochk.io's
`/api/tally`, both implementations agree. If they don't — trust the CLI.

Pipe it into anything:

```bash
# CI-style gate
RESULT=$(npx -y @orangecheck/vote-cli tally "$POLL_ID" --json | jq -r '.tallies.yes > .tallies.no')
[[ "$RESULT" == "true" ]] && ./deploy.sh
```

## embed the tally as a Nostr-native signal

Because polls and ballots live on Nostr (kinds 30080 / 30081 / 30082), any Nostr
client can subscribe to a poll's ballots without touching vote.ochk.io at all.
Filter:

```json
{ "kinds": [30081], "#t": ["<poll_id>"] }
```

Filter on `#t`: relays index single-letter tags only, and most reject a filter
on a longer name such as `#poll_id`.

Parse each event's `content` as a Ballot and feed them to `tally()`, which
checks each ballot's BIP-322 signature over its `ballotId()` against `voter` and
drops the ones that fail.

## tally it yourself

Everything vote.ochk.io does, in one script: the poll and its ballots from the
default relays, the snapshot block, UTXOs from mempool.space, and the pure
function. Run on the poll above, it prints the same `snapshot_block`, `turnout`
and `tallies` as `/api/tally` and the CLI.

<InstallTabs pkg="@orangecheck/vote-core @orangecheck/nostr-core @orangecheck/bip322" />

```ts
import type { Ballot, Poll, Utxo } from '@orangecheck/vote-core';

import { verifySignature } from '@orangecheck/bip322';
import { queryEvents } from '@orangecheck/nostr-core';
import {
    mempoolBlockTimeSource,
    pollId,
    resolvePollSnapshot,
    tally,
} from '@orangecheck/vote-core';

const id = '9825268c74a3a15baefe8f9705f774cc7bb97205922fc828df3b377e0e158a18';
const parse = <T>(content: string): T | null => {
    try {
        return JSON.parse(content) as T;
    } catch {
        return null;
    }
};

// 1. The poll (the event whose content hashes to the id) and its ballots.
const { events: pollEvents } = await queryEvents({
    kinds: [30080],
    '#t': [id],
});
const poll = pollEvents
    .map((e) => parse<Poll>(e.content))
    .find((p) => p && pollId(p) === id);
if (!poll) throw new Error('poll not found on any relay that answered');
const { events: ballotEvents } = await queryEvents({
    kinds: [30081],
    '#t': [id],
});
const ballots = ballotEvents
    .map((e) => parse<Ballot>(e.content))
    .filter((b): b is Ballot => b !== null);

// 2. The snapshot block: the poll's own height, or the block at its deadline.
const snap = await resolvePollSnapshot(poll, mempoolBlockTimeSource());
if (!snap.ok) throw new Error(`${snap.code}: ${snap.reason}`);

// 3. UTXOs from mempool.space: coins unspent now and confirmed by the snapshot.
//    Coins spent after the snapshot are missed; your own node can count them.
const utxosAt = async (address: string, height: number): Promise<Utxo[]> => {
    const res = await fetch(
        `https://mempool.space/api/address/${address}/utxo`
    );
    const utxos = (await res.json()) as {
        value: number;
        status: { confirmed: boolean; block_height?: number };
    }[];
    return utxos
        .filter((u) => u.status.confirmed && u.status.block_height! <= height)
        .map((u) => ({
            value: u.value,
            confirmed_height: u.status.block_height!,
        }));
};

const result = await tally({
    poll,
    ballots,
    snapshotBlock: snap.height,
    utxosAt,
    verify: ({ address, message, signature }) =>
        verifySignature(address, message, signature),
});
console.log(JSON.stringify(result));
```

`queryEvents` reports which relays answered in `relayStatus`; a relay that did
not answer is not evidence that a ballot is missing.

## gate a Discord bot

```ts
// Called from your bot's command handler; reply and grantRole are your bot's.
async function onPollCommand(pollId: string, user: string) {
    const res = await fetch(`https://vote.ochk.io/api/tally?poll=${pollId}`);
    const result = (await res.json()) as {
        state: string;
        tallies?: Record<string, number>;
    };
    if (result.state !== 'tallied' || !result.tallies)
        return reply('poll still open');
    const passed = (result.tallies.yes ?? 0) > (result.tallies.no ?? 0);
    if (passed) await grantRole(user);
}
```

For long-running votes, poll `/api/tally` every 5 minutes; for settled
decisions, run one CLI verification at close.

## gate a forum / submission queue

- Post creation requires signing the submission against the poster's Bitcoin
  address (BIP-322).
- Before admitting the post, verify the poster's OC Vote threshold: either by
  running a fresh OC Vote tally against a currently-running "membership" poll,
  or by checking a specific ballot event.

## weight a DAO executor

DAO governance frameworks can treat an OC Vote tally as the oracle for an
on-chain execution. Pattern:

1. A DAO contract waits for a specific `poll_id` to close.
2. A signer (any honest observer) submits the tally + a proof (all ballot
   events + UTXO snapshot root) to the contract.
3. The contract verifies the tally by running the pure function in-contract OR
   by checking that N independent signers agree on the result.

OC Vote does not prescribe the on-chain half — you write that half in whatever
chain's language suits you. The contribution is: a _reproducible,
sybil-resistant, offline-verifiable_ result that any honest observer produces
byte-identically.

## ballot-cast-on-behalf flows

The protocol does not currently specify delegation (see
`oc-vote-protocol/SPEC.md` §13 "Future work"). For now, voters sign their own
ballots. If you need proxy voting, have the proxy address itself be credibly
bonded and have delegators publish a separate signed "I delegate to bc1q..."
message that your client interprets.

## self-host the tallier

If you care about the tallier's availability:

```bash
git clone https://github.com/orangecheck/oc-vote-protocol
npm i @orangecheck/vote-core @orangecheck/vote-cli
# self-host the Nostr relay set if you want end-to-end independence
```

The tally function has zero external dependencies beyond: a Bitcoin node (or any
explorer), a Nostr relay set (or raw event JSON), and BIP-322 verification.
vote.ochk.io is convenience; correctness is the library.
