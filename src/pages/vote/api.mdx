## http

```
GET /api/tally?poll=<64-char hex poll_id>
```

Fetches the poll from the default Nostr relay set, pulls every matching ballot,
verifies every BIP-322 signature, resolves the snapshot block, looks up UTXOs
from mempool.space, runs the pure tally function, and returns JSON.

**200 tallied:**

```json
{
    "poll_id": "9825268c…",
    "state": "tallied",
    "snapshot_block": 947961,
    "turnout": { "voters": 1, "weight": 12311 },
    "tallies": { "yes": 12311, "no": 0 },
    "ballot_count": 1,
    "reveal_published": false,
    "relays": [{ "relay": "wss://relay.ochk.io", "answered": true, "events": 1 }, …],
    "utxo_source": {
        "explorer": "mempool.space",
        "counts": "coins unspent now and confirmed at or before snapshot_block",
        "not_counted": "coins spent after snapshot_block"
    }
}
```

**200 awaiting_reveal (secret-mode poll pre-close):**

```json
{ "poll_id": "cc27…", "state": "awaiting_reveal" }
```

**Errors** (JSON with an `error` string):

- `400` — poll query param missing or not 64 hex.
- `404` — no relay that answered holds the poll. If the id is a poll's Nostr
  event id, the body names the `poll_id` to use instead.
- `409` — `state: "deferred"`: the snapshot block is not yet buried six blocks
  deep. Retry later.
- `422` — the poll event's content did not match the poll id.
- `503` — no relay finished answering the poll, ballot or reveal query. A tally
  over a ballot set no relay finished sending would be a guess.

Response is cached for 60 seconds at the edge. Live tallies on the poll page
recompute client-side against the same function.

### example: build and sign a poll

```ts
import type { Poll } from '@orangecheck/vote-core';

import { pollId } from '@orangecheck/vote-core';

const iso = (ms: number) =>
    new Date(ms).toISOString().replace(/\.\d{3}Z$/, 'Z');

const draft: Poll = {
    v: 0,
    kind: 'oc-vote/poll',
    creator: 'bc1q…',
    question: 'Should we ship?',
    options: [
        { id: 'yes', label: 'Yes' },
        { id: 'no', label: 'No' },
    ],
    deadline: iso(Date.now() + 7 * 86_400_000), // MUST be in the future when published
    snapshot_block: 'deadline',
    weight_mode: 'sats',
    weight_params: null,
    min_sats: 100_000,
    min_days: 30,
    mode: 'public',
    reveal_pk: null,
    tiebreak: 'latest',
    notes: null,
    created_at: iso(Date.now()),
    sig: { alg: 'bip322', pubkey: 'bc1q…', value: '' },
};

const id = pollId(draft);
// ask the wallet to BIP-322 sign `id` (the 64-hex string), then:
draft.sig.value = await walletSignBIP322(id);
```

### example: tally

```ts
import { verifySignature } from '@orangecheck/bip322';
import {
    mempoolBlockTimeSource,
    resolvePollSnapshot,
    tally,
} from '@orangecheck/vote-core';

const snap = await resolvePollSnapshot(poll, mempoolBlockTimeSource());
if (!snap.ok) throw new Error(`${snap.code}: ${snap.reason}`);

const result = await tally({
    poll,
    ballots,
    snapshotBlock: snap.height, // required when poll.snapshot_block is "deadline"
    utxosAt: (addr, snapshotHeight) => myUtxoSource.fetch(addr, snapshotHeight),
    // Named arguments: vote-core's positional verifyBip322 takes
    // (address, message, signature), unlike every sibling package.
    verify: ({ address, message, signature }) =>
        verifySignature(address, message, signature),
});
```

The library is **pure**. Same inputs → byte-identical output across
implementations. It passes the six canonical fixtures in
[`oc-vote-protocol/test-vectors/`](https://github.com/orangecheck/oc-vote-protocol/tree/main/test-vectors).

## dispute resolution

If the vote.ochk.io page tally disagrees with yours:

```bash
npx -y @orangecheck/vote-cli tally <poll_id>
# or: git clone oc-vote-protocol && implement tally() yourself
```

Whoever matches the canonical fixtures + the spec is correct. The web page is a
convenience over the same function any client can run.
